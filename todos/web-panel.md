# Web-панель

Цель: сделать панель удобным интерфейсом кампании для мастера и игроков, сохранив Core лёгким и
пригодным для Raspberry Pi.

## Интерфейс

- [x] `WEB-001` Отделить HTML/CSS от HTTP routing в `src/web/server.py`: Jinja environment
  и файловые шаблоны вынесены в `src/web/views.py` и `src/web/templates/`.
- [x] `WEB-002` Сделать адаптивную структуру страниц для телефона и desktop: mobile-first карточки
  перестраиваются в двухколоночную сетку на широких экранах.
- [x] `WEB-003` Добавить единый layout, навигацию, состояния ошибок и пустых списков: общий header,
  dashboard-карточки и message page используют одну визуальную систему.
- [x] `WEB-004` Сохранить реализацию без тяжёлого frontend toolchain: server-side Jinja
  не требует Node.js или сборки frontend assets.
- [x] `WEB-005` Добавить ручной выбор светлой, тёмной или системной темы с сохранением
  настройки в браузере.
- [x] `WEB-006` Вывести на панели последние завершённые игровые сессии кампании.
- [x] `WEB-007` Вводить дату и 24-часовое время в локальном часовом поясе браузера,
  сохраняя момент игры в UTC.
- [x] `WEB-008` Добавить страницу настроек кампании: название, Foundry URL, часовой пояс
  закреплённого расписания и оформление.
- [x] `WEB-009` Добавить публичную стартовую страницу с описанием панели и явными ссылками
  на локальный вход и регистрацию.

## Пользователи и роли

- [x] `WEB-101` Описать права ролей: игрок и мастер задаются членством в конкретной кампании;
  администратор платформы остаётся отдельной глобальной ролью.
- [x] `WEB-102` Добавить локальный вход в панель для зарегистрированных игроков с привязкой
  аккаунта к Telegram ID через одноразовый код бота.
- [x] `WEB-103` Ограничивать данные и действия текущей кампанией пользователя.
- [ ] `WEB-104` Постепенно переносить управление кампанией из Telegram в web, оставляя бота
  быстрым пультом и каналом уведомлений.
  - [x] `WEB-104A` Разрешить мастеру переименовывать персонажа и исключать игрока из кампании,
    сохраняя исторические данные персонажа.
  - [x] `WEB-104B` Генерировать через бота одноразовое приглашение в Telegram-чат кампании;
    membership создаётся только после вступления и регистрации командой `/player`.
  - [ ] `WEB-104C` Добавить передачу роли мастера с явным подтверждением.
  - [ ] `WEB-104D` Спроектировать создание и архивирование кампаний вне Telegram-чата.

## Аутентификация и безопасность

- [x] `WEB-201` Вынести аутентификацию за интерфейс `IdentityProvider` и реализовать локальный
  логин с регистрацией через одноразовый код Telegram-бота. Telegram OIDC оставить будущим
  адаптером после появления стабильного публичного URL.
- [x] `WEB-202` Заменить in-memory сессии на SQLite-хранилище с явным сроком жизни и отзывом,
  доступное через заменяемый интерфейс `WebSessionStore`.
- [x] `WEB-203` Добавить logout и просмотр/отзыв активных сессий.
- [x] `WEB-204` Добавить CSRF-защиту для всех изменяющих запросов.
- [x] `WEB-205` Корректно учитывать HTTPS и доверенные proxy headers за reverse proxy.
- [x] `WEB-206` Добавить сохраняемый в SQLite rate limiting для входа, регистрации и выпуска
  `/admin`-ссылок и регистрационных кодов через заменяемый интерфейс `RateLimiter`.
- [x] `WEB-207` Покрыть авторизацию негативными тестами: чужая кампания, отозванная сессия,
  просроченный токен и повторное использование ссылки.

Одноразовая ссылка `/admin` остаётся рабочим быстрым входом мастера. Полноценный Telegram Login
через OIDC запланирован после появления стабильного публичного URL панели.
