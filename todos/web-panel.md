# Web-панель

Цель: сделать панель удобным интерфейсом кампании для мастера и игроков, сохранив Core лёгким и
пригодным для Raspberry Pi.

## Интерфейс

- [ ] `WEB-001` Отделить HTML/CSS от HTTP routing в `src/web/server.py`.
- [ ] `WEB-002` Сделать адаптивную структуру страниц для телефона и desktop.
- [ ] `WEB-003` Добавить единый layout, навигацию, состояния ошибок и пустых списков.
- [ ] `WEB-004` Сохранить реализацию без тяжёлого frontend toolchain, пока он не станет необходим.

## Пользователи и роли

- [ ] `WEB-101` Описать права ролей: игрок, мастер и администратор платформы.
- [ ] `WEB-102` Добавить вход в панель для зарегистрированных игроков.
- [ ] `WEB-103` Ограничивать данные и действия текущей кампанией пользователя.
- [ ] `WEB-104` Постепенно переносить управление кампанией из Telegram в web, оставляя бота
  быстрым пультом и каналом уведомлений.

## Аутентификация и безопасность

- [ ] `WEB-201` Выбрать механизм идентификации: Telegram Login Widget, magic link или отдельные
  учётные данные; оформить решение до реализации.
- [ ] `WEB-202` Заменить in-memory сессии на хранилище с явным сроком жизни и отзывом.
- [ ] `WEB-203` Добавить logout и просмотр/отзыв активных сессий.
- [ ] `WEB-204` Добавить CSRF-защиту для всех изменяющих запросов.
- [ ] `WEB-205` Корректно учитывать HTTPS и доверенные proxy headers за reverse proxy.
- [ ] `WEB-206` Добавить rate limiting для входа и выпуска ссылок.
- [ ] `WEB-207` Покрыть авторизацию негативными тестами: чужая кампания, отозванная сессия,
  просроченный токен и повторное использование ссылки.

Одноразовая ссылка `/admin` остаётся рабочим bootstrap-механизмом до появления и проверки новой
схемы входа.
