# Changelog

Все заметные изменения проекта будут документироваться в этом файле. Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии следуют [Semantic Versioning](https://semver.org/lang/ru/).

## [Unreleased]

- Добавлена публичная стартовая страница web-панели с описанием возможностей и явными кнопками
  входа и регистрации вместо ответа `401` на корневом адресе.
- `WEB-206`: добавлен сохраняемый SQLite rate limiting локального входа, регистрации,
  `/admin`-ссылок и регистрационных кодов с ответом `429` и заголовком `Retry-After`.
- `WEB-104A`: мастер может переименовать персонажа или исключить игрока из кампании через web;
  запись персонажа сохраняется для истории сессий и рекапов.
- `WEB-104B`: мастер может запросить через web одноразовое приглашение в Telegram-чат кампании;
  бот отправляет его игроку или мастеру для пересылки, а membership заранее не создаётся.
- `WEB-104C`: мастер может передать управление кампанией существующему игроку через web с явным
  подтверждением; прежний мастер остаётся участником с ролью игрока.
- Аутентификация web-панели вынесена в заменяемый `IdentityProvider`: добавлены локальные
  аккаунты, защищённые `scrypt`, страницы входа и регистрации и команда `/web_register` для
  привязки аккаунта к подтверждённому Telegram ID одноразовым кодом.
- Полноценный Telegram OIDC-вход отложен до появления стабильного публичного URL; существующий
  быстрый вход через `/admin` сохранён.
- `WEB-207`: добавлены отрицательные тесты авторизации для чужой кампании, отозванной сессии,
  просроченных регистрационного и login-токенов и повторного использования magic-link.
- В web-панели появился сохраняемый переключатель светлой, тёмной и системной темы.
- Панель мастера показывает последние десять завершённых игр кампании.
- Время игры в web-панели вводится в локальном часовом поясе браузера в 24-часовом формате.
- Добавлена страница настроек кампании с названием, Foundry URL и часовым поясом закрепа.
- Карточки web-панели теперь корректно меняют фон вместе со светлой и тёмной темой.
- Клиентская логика web-панели вынесена в небольшой JS-файл: добавлены локальное время,
  проверка даты, подтверждение завершения сессии и состояние отправки форм.
- Добавлены выход из web-панели с отзывом текущей сессии и CSRF-защита изменяющих форм.
- Добавлена страница просмотра и отзыва активных web-сессий кампании.
- `X-Forwarded-Proto` учитывается только для явно настроенных доверенных reverse proxy.
- Добавлена модель пользователей и членства в кампаниях: один человек может иметь разные роли
  игрока и мастера в разных кампаниях.
- После web-входа доступен выбор всех кампаний пользователя; роль и доступ проверяются заново
  для каждой выбранной кампании.
- Login-токены и web-сессии сохраняются в SQLite через интерфейс `WebSessionStore`; в базе
  хранятся только хеши bearer-токенов, а backend можно заменить без изменения HTTP-слоя.

### Changed

- `WEB-ARCH-001` (этап 1): HTTP request/response, маршрутизация и trusted proxy/cookie middleware
  вынесены из `AdminWebServer` в отдельные модули с сохранением совместимости существующих handlers.
- `ARCH-004`: добавлены AST-тесты архитектурных границ между web, Telegram-командами, domain,
  repositories и database owner; запрещённые импорты теперь приводят к падению test suite.
- `ARCH-003`: общие модели кампаний, пользователей, членства, персонажей, сессий и рекапов
  перенесены из database-слоя в независимый пакет `domain`; репозитории теперь возвращают domain-модели.
- `ARCH-002`: общая логика расписания и форматирования анонсов вынесена в нейтральный пакет `game`;
  web-слой больше не импортирует Telegram-команды или библиотеку Telegram.
- `ARCH-001`: Core-зависимые Telegram-команды переведены на единственный путь через `CoreClient`;
  удалены локальные service lookup и legacy lifecycle-тесты, standalone-команды бросков и утилит сохранены.
- `WEB-001`, `WEB-004`: HTML/CSS вынесены из HTTP routing в Jinja-шаблоны с autoescape
  и inheritance, без frontend toolchain.
- `WEB-002`, `WEB-003`: панель получила адаптивный mobile-first layout, общую навигацию, карточки,
  улучшенные формы и отдельные состояния ошибок и пустых данных.

### Fixed

- `/admin` в личном чате объясняет, что команду нужно вызвать в группе кампании; отказы
  Core при выпуске admin-ссылки теперь пишут причину в структурированный лог.

## [0.13.0] - 2026-07-16

### Added

- Heartbeat liveness и Telegram API readiness для standalone Compose и Kubernetes probes.
- `DICE-002`: структурированный результат броска с исходным выражением, костями,
  модификатором и итогом.
- `DICE-003`: Foundry-совместимые модификаторы выбора костей `k`, `kh` и `kl` с
  необязательным количеством.
- `DICE-004`: команда `/reroll` для повтора последнего успешного броска с новыми
  случайными значениями.

### Fixed

- Временная недоступность Telegram API больше не переводит bot-контейнер в `unhealthy`
  и не валит deploy: `getMe` пишет warning, но не влияет на exit code, а timeout runtime-проверки
  больше сетевого timeout.
- `DICE-001`: ошибки parser теперь объясняют причину и указывают проблемный фрагмент
  выражения.
- `DICE-005`: проверены и задокументированы лимиты костей, граней и длины
  выражения.
- Backup-соединения SQLite явно закрываются и больше не создают `ResourceWarning`.
- Healthcheck warnings и operational-поля web-сервера выводятся в JSON-логах.
- Dev и production Core используют разные внешние порты по умолчанию и больше не конфликтуют при
  одновременном deploy на одном Raspberry Pi.

### Changed

- Runtime Docker-образ больше не содержит сборщик `uv`; production-зависимости
  копируются из отдельного builder-stage.

## [0.12.0] - 2026-07-16

### Added

- SQLite-модуль с миграциями, репозиториями и постоянным Docker volume.
- Расписание следующей игры с Foundry-ссылкой и автоматическим закреплением в Telegram.
- Ссылка Foundry по умолчанию через `D20_BOT_FOUNDRY_URL` с возможностью переопределения в `/game`.
- Опциональный контейнер `sqlite-web` в Compose-профиле `debug` для просмотра базы.
- Команда `/game_url` для сохранения адреса Foundry по умолчанию для конкретного чата.
- Автоматическое включение Compose-профиля `debug` при deploy ветки `dev`.
- Единая модель planned/active/finished для расписания и игровых сессий.
- Команды `/session_start` и `/session_stop` для жизненного цикла игровых сессий.
- Роли мастера и игроков, а также Telegram member tags персонажей через `/player`.
- Сервисный слой для сценариев кампаний, расписания и сессий.
- Раздельные Telegram-модули для ролей, member tags и жизненного цикла сессий.
- Команды расписания и настройки Foundry разделены; разбор даты и URL вынесен в чистые утилиты.
- Типизированные статусы для регистрации игрока, запуска и остановки сессии.
- Сервисы создаются один раз на lifecycle приложения.
- Встроенная лёгкая веб-панель для просмотра и переноса следующей игры.
- Команда `/admin` с одноразовой ссылкой и HttpOnly-сессией мастера.
- Команда `/web_url` для хранения адреса панели отдельно для каждого чата.
- Запуск и завершение игровой сессии из панели мастера.
- Отображение мастера и состава персонажей в веб-панели.
- Standalone-режим без SQLite, миграций, web-сервера и управляющих Telegram-команд.
- Отдельный Core-процесс с внутренним API и Compose-профилем `platform`.
- Connected-режим со всеми управляющими командами через Core API, без прямого доступа бота
  к SQLite.
- Постоянный SQLite-outbox для доставки событий веб-панели Telegram-боту.
- Helm chart для standalone и connected-развёртывания в Kubernetes.
- Единый префикс `D20_BOT_` для переменных окружения приложения и deploy-конфигурации.
- Health endpoint Core и readiness-проверка всех Compose-сервисов при deploy.
- Автоматический согласованный backup production SQLite в отдельный Docker volume перед
  миграциями с настраиваемой ротацией копий.

### Fixed

- Права пользователя контейнера на `/data` для создания SQLite-файла в Docker volume.
- Абсолютный путь SQLite по умолчанию при запуске без `D20_BOT_DATABASE_URL`.
- Дублирование данных между `game_schedules` и `sessions`: расписание перенесено в сессии.
- Диагностика ошибок Telegram API при установке member tags в структурированных логах.
- Понятный ответ на Core-команды, вызванные в standalone-режиме.
- Подготовка прав SQLite volume вынесена в одноразовый инфраструктурный сервис `data-init`.
- Фоновый Core poller корректно управляется lifecycle бота и пишет причину транспортной ошибки.

### Removed

- Монолитный `D20_BOT_MODE=full`; Telegram-бот больше не открывает SQLite и не запускает web.
- `D20_BOT_TG_TOKEN` и прямые Telegram API-вызовы из Core.
- Параллельные запросы `/session_start` больше не могут создать две активные сессии.
- SQLite-исключение конфликта active-сессии больше не протекает в сервисный и Telegram-слои.
- Быстрое Telegram-меню сокращено до `/roll`, `/roll20` и `/duality`; полный список остался в `/help`.

## [0.11.1] - 2026-07-11

### Added

- Telegram-команды бросков, Daggerheart и таймеров.
- JSON-логи, Docker deployment и GitHub Actions.
- Расширенные броски `kh` и `kl`.
- Structured observability с request/update/user IDs и latency.
- Управление зависимостями через uv lockfile.
