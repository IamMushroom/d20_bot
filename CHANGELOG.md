## [0.12.0] - 2026-07-16

### Added

- SQLite-модуль с миграциями, репозиториями и постоянным Docker volume.
- Расписание следующей игры с Foundry-ссылкой и автоматическим закреплением в Telegram.
- Ссылка Foundry по умолчанию через `D20_BOT_FOUNDRY_URL` с возможностью переопределения в `/game`.
- Опциональный контейнер `sqlite-web` в Compose-профиле `debug` для просмотра базы.
- Команда `/game_url` для сохранения адреса Foundry по умолчанию для конкретного чата.
- Автоматическое включение Compose-профиля `debug` при deploy ветки `dev`.
- Единая модель planned/active/finished для расписания и игровых сессий.
- Команды `/session_start` и `/session_stop` для жизненного цикла игровых сессий.
- Роли мастера и игроков, а также Telegram member tags персонажей через `/player`.
- Сервисный слой для сценариев кампаний, расписания и сессий.
- Раздельные Telegram-модули для ролей, member tags и жизненного цикла сессий.
- Команды расписания и настройки Foundry разделены; разбор даты и URL вынесен в чистые утилиты.
- Типизированные статусы для регистрации игрока, запуска и остановки сессии.
- Сервисы создаются один раз на lifecycle приложения.
- Встроенная лёгкая веб-панель для просмотра и переноса следующей игры.
- Команда `/admin` с одноразовой ссылкой и HttpOnly-сессией мастера.
- Команда `/web_url` для хранения адреса панели отдельно для каждого чата.
- Запуск и завершение игровой сессии из панели мастера.
- Отображение мастера и состава персонажей в веб-панели.
- Standalone-режим без SQLite, миграций, web-сервера и управляющих Telegram-команд.
- Отдельный Core-процесс с внутренним API и Compose-профилем `platform`.
- Connected-режим со всеми управляющими командами через Core API, без прямого доступа бота
  к SQLite.
- Постоянный SQLite-outbox для доставки событий веб-панели Telegram-боту.
- Helm chart для standalone и connected-развёртывания в Kubernetes.
- Единый префикс `D20_BOT_` для переменных окружения приложения и deploy-конфигурации.
- Health endpoint Core и readiness-проверка всех Compose-сервисов при deploy.
- Автоматический согласованный backup production SQLite в отдельный Docker volume перед
  миграциями с настраиваемой ротацией копий.

### Fixed

- Права пользователя контейнера на `/data` для создания SQLite-файла в Docker volume.
- Абсолютный путь SQLite по умолчанию при запуске без `D20_BOT_DATABASE_URL`.
- Дублирование данных между `game_schedules` и `sessions`: расписание перенесено в сессии.
- Диагностика ошибок Telegram API при установке member tags в структурированных логах.
- Понятный ответ на Core-команды, вызванные в standalone-режиме.
- Подготовка прав SQLite volume вынесена в одноразовый инфраструктурный сервис `data-init`.
- Фоновый Core poller корректно управляется lifecycle бота и пишет причину транспортной ошибки.

### Removed

- Монолитный `D20_BOT_MODE=full`; Telegram-бот больше не открывает SQLite и не запускает web.
- `D20_BOT_TG_TOKEN` и прямые Telegram API-вызовы из Core.
- Параллельные запросы `/session_start` больше не могут создать две активные сессии.
- SQLite-исключение конфликта active-сессии больше не протекает в сервисный и Telegram-слои.
- Быстрое Telegram-меню сокращено до `/roll`, `/roll20` и `/duality`; полный список остался в `/help`.

## [0.11.1] - 2026-07-11

### Added

- Telegram-команды бросков, Daggerheart и таймеров.
- JSON-логи, Docker deployment и GitHub Actions.
- Расширенные броски `kh` и `kl`.
- Structured observability с request/update/user IDs и latency.
- Управление зависимостями через uv lockfile.
- SBOM, provenance и ARM64 CI/CD.
