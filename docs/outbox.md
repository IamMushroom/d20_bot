# Outbox-события

Transactional outbox передаёт от Core connected-боту данные о произошедших операциях. Core
сохраняет event вместе с изменением состояния, а бот подтверждает его только после успешного
Telegram side effect. Доставка имеет семантику at-least-once: повторная обработка возможна.

Envelope internal API содержит `id`, `type` и `payload`. Отдельное версионирование и служебные
metadata пока не нужны: все события создаёт и потребляет одна версия приложения.

## `game_scheduled`

Обязательные поля: `chat_id`, `session_id`, `scheduled_at`, `timezone`, `foundry_url`.
`scheduled_at` — timezone-aware ISO 8601 datetime. Опциональное поле `previous_message_id`
содержит ID предыдущего закрепа.

Бот форматирует объявление, отправляет и закрепляет его, сохраняет новый Telegram message ID в
Core и снимает предыдущий закреп, если он указан. Payload не содержит готового текста.

## `session_started`

Обязательные поля: `chat_id`, `number`. Опциональные: `title`, `announcement_message_id`.
Бот снимает закреп расписания, если он указан, и отправляет сообщение о начале сессии.

## `session_stopped`

Обязательные поля: `chat_id`, `number`. Бот отправляет сообщение о завершении сессии.

## `player_invited`

Обязательные поля: `chat_id`, `requester_user_id`, `target_user_id`, `character_name`. Бот
создаёт одноразовую Telegram-ссылку на 24 часа и отправляет её игроку. Если бот не может написать
игроку, ссылка отправляется запросившему приглашение мастеру.

## Ошибки и повторная доставка

Невалидное или неизвестное событие не подтверждается. Ошибка Telegram или Core также оставляет
событие неподтверждённым, и poller повторит его позднее. Exactly-once не гарантируется. Для
предсказуемой обработки расписания используются `session_id` и `previous_message_id`; отдельное
хранилище дедупликации не вводится.
