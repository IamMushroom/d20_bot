# Web-аутентификация

## Архитектура

Аутентификация вынесена в пакет `src/auth`. Core зависит от протокола `IdentityProvider`, а не
от SQLite или конкретного способа входа. Текущая реализация — `SQLiteLocalIdentityProvider`;
Telegram Login в будущем можно добавить отдельным адаптером.

```text
bot → внутренний API Core → IdentityProvider
web → IdentityProvider → telegram_user_id → campaign_memberships
```

Учётная запись глобальна и связана с `users.telegram_user_id`. Права не хранятся в аккаунте:
роль игрока или мастера определяется отдельно для каждой кампании через `campaign_memberships`.

## Локальная регистрация

1. Зарегистрированный участник вызывает `/web_register` у Telegram-бота.
2. Бот просит Core выпустить одноразовый код и отправляет его пользователю в личные сообщения.
3. Пользователь открывает `/register`, вводит код, логин и пароль.
4. Core связывает локальный аккаунт с подтверждённым Telegram ID и создаёт HttpOnly web-сессию.

Код действует 15 минут. В SQLite хранится только его SHA-256-хеш; повторное использование
невозможно. Логин состоит из 3–32 латинских букв, цифр, точки, дефиса или подчёркивания. Пароль
должен содержать от 10 до 256 символов и хранится как `scrypt`-хеш с индивидуальной случайной
солью.

Попытки входа и регистрации ограничиваются по IP, а выпуск `/admin`-ссылок и регистрационных
кодов — по Telegram user ID. Счётчики хранятся в SQLite через заменяемый `RateLimiter`, поэтому
не сбрасываются при перезапуске Core. При превышении лимита сервер отвечает `429` и сообщает
время ожидания в заголовке `Retry-After`.

Обычный вход выполняется на `/login`. Существующие одноразовые ссылки `/admin` сохранены и
продолжают работать как быстрый вход мастера.

## Сессии

После любого способа подтверждения личности используется существующая HttpOnly-сессия через
`WebSessionStore`. TTL, CSRF-защита, просмотр и отзыв сессий не зависят от `IdentityProvider`.
SQLite остаётся текущим backend; Redis/Valkey можно подключить отдельным адаптером хранилища.

## Будущий Telegram Login

Полноценный вход через Telegram отложен до появления стабильного публичного URL панели.
Предпочтительный вариант — Telegram OpenID Connect, Authorization Code Flow с PKCE, проверкой
`state`, `nonce`, ID token и JWKS. После проверки адаптер должен вернуть тот же
`telegram_user_id`; остальная часть Core и модель прав не изменятся.
